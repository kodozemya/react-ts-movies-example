# Приклад: Типізований React-застосунок

Еталонний розв'язок бою з босом регіону **«Альянс Реакту й Типів»**.
Той самий каталог фільмів, що і в [`example-react-movies`](../example-react-movies),
переписаний на TypeScript (шаблон Vite `react-ts`).

Макет: [Movie Listing Web App](https://www.figma.com/design/0FpFMQzeL2Q35MOiRlgySt/Movie-Listing-Web-App?node-id=401-6827)
— сторінка **Web App** (екрани Home, Movies, TV Shows, Details Page).

> Порівняй два репозиторії файл до файла — різниця між ними і є змістом
> цього бою. JavaScript-версія лишається на місці навмисно: у портфоліо
> дві версії одного застосунку читаються краще, ніж один переписаний.

## Як запустити

```bash
npm install
cp .env.example .env    # і встав туди свій токен TMDB (як його взяти — нижче)
npm run dev
npm run typecheck       # tsc -b — має завершитися без жодної помилки
```

Далі відкрий адресу, яку покаже Vite — зазвичай http://localhost:5173.

## Як отримати токен TMDB

Це найдовша частина інструкції, бо саме тут застрягають найчастіше.
Реєстрація безкоштовна й безстрокова, картка не потрібна.

### Крок 1. Обліковий запис

Зареєструйся на [themoviedb.org/signup](https://www.themoviedb.org/signup)
і **підтверди пошту** — лист приходить одразу.

> Поки пошта не підтверджена, сторінка налаштувань API не відкриється
> і покаже помилку без пояснення. Якщо листа немає — перевір «Спам».

### Крок 2. Сторінка API

Відкрий [themoviedb.org/settings/api](https://www.themoviedb.org/settings/api)
(це ж саме: аватар праворуч вгорі → **Settings** → пункт **API** у лівому меню).

> В офіційній документації є окреме попередження: форму реєстрації API
> **не пристосовано до телефона**. Роби це з комп'ютера.

### Крок 3. Заявка на ключ

Натисни **Request an API Key** і обери план **Developer** — він
безкоштовний. Треба буде прийняти умови використання.

Далі — анкета. Що писати студентові, у якого проєкту ще немає:

| Поле | Що писати |
| --- | --- |
| Type of Use | `Education` (або `Website` — обидва підходять) |
| Application Name | Назва твого навчального проєкту, напр. `Movie Catalog` |
| Application URL | Проєкт ще не в мережі? Пиши `http://localhost:5173` або посилання на свій GitHub |
| Application Summary | Чесно: `A personal learning project — a React movie catalog for educational purposes only` |
| Ім'я, адреса, телефон | Справжні; це лише для їхнього обліку |

Схвалення зазвичай **миттєве**, зрідка — за кілька годин.

### Крок 4. Взяти саме той рядок

Після схвалення на сторінці [settings/api](https://www.themoviedb.org/settings/api)
з'являться **два різні** значення. Це місце, де плутаються всі:

| | Вигляд | Як передається |
| --- | --- | --- |
| **API Key** | 32 символи: `a1b2c3d4e5…` | у query-параметрі `?api_key=…` |
| **API Read Access Token** | дуже довгий, починається на `eyJ` | у заголовку `Authorization: Bearer …` |

**Цьому проєкту потрібен другий — API Read Access Token.** Той, що
починається на `eyJ`.

### Крок 5. Вставити токен у проєкт

Відкрий `.env` (той, що зробив командою `cp .env.example .env`) і встав:

```
VITE_TMDB_TOKEN=eyJhbGciOiJIUzI1NiJ9....
```

Префікс `VITE_` обов'язковий, лапки не потрібні, а `npm run dev` після
цього треба **перезапустити**: `.env` читається один раз на старті.

> Повний розбір з поясненнями, перевіркою через `curl` і таблицею
> «що бачиш → що сталося» — у
> [README JavaScript-версії](../example-react-movies#як-отримати-токен-tmdb).

## Чому `tsc -b`, а не `tsc --noEmit`

Це найкорисніший рядок у всьому README.

Кореневий `tsconfig.json` шаблону `react-ts` — це **solution-конфіг**:

```json
{ "files": [], "references": [{ "path": "./tsconfig.app.json" }, ...] }
```

`"files": []` означає «жодного файла». Тому `tsc --noEmit` перевіряє
**порожню множину** й радісно завершується успіхом навіть на проєкті,
який не збирається. Прапорець `-b` (build) каже компілятору пройти
за посиланнями `references` і перевірити кожен підпроєкт по-справжньому.

Перевір сам: додай у будь-який компонент рядок `const x: number = "текст";`
і запусти обидві команди.

## Структура

```

  index.css              усі стилі застосунку
  vite-env.d.ts          типи змінних оточення (VITE_TMDB_TOKEN)
  types/tmdb.ts          сирі типи TMDB і наш MediaItem — межа з мережею
  api/tmdb.ts            адреса, токен, перевірка response.ok
  lib/media.ts           приведення відповідей TMDB до однієї форми
  hooks/useTmdb.ts       базовий запит: дані, завантаження, помилка, скасування
  hooks/useDebounced.ts  затримка для живого пошуку
  hooks/useMedia.ts      useMediaList(вкладка, запит) і useMediaDetails(тип, id)
  components/
    Header.tsx           навбар
    SearchField.tsx      поле пошуку з іконкою
    FilterTabs.tsx       вкладки «Усі / Фільми / Серіали»
    MediaGrid.tsx        сітка карток
    MediaCard.tsx        одна картка
    StatusMessage.tsx    завантаження / помилка / порожньо
    ScrollToTop.tsx      прокрутка вгору після переходу
    icons.tsx            спільні іконки
  pages/

    DetailsPage.tsx      сторінка /title/:mediaType/:id

```

Межі ті самі, що й у JavaScript-версії: **компонент або малює, або керує
даними, але не обидва одночасно.** Додався лише один файл — `types/tmdb.ts`,
і саме він тут найважливіший.

## Де тут справді працюють типи

Цей проєкт обрано не випадково: у ньому є місце, де TypeScript дає
не «менше одруківок», а нову можливість — **розмічене об'єднання**.

TMDB віддає списки, у яких лежать три різні речі: фільми, серіали й люди.

```ts
export type TmdbListItem = TmdbMovie | TmdbTv | TmdbPerson;
```

Далі `lib/media.ts` користується цим так:

```ts
// Захисник типу: після нього компілятор ЗНАЄ, що людей уже немає
export function isTitle(item: TmdbListItem): item is TmdbMovie | TmdbTv {
  return item.media_type !== "person";
}

// Звуження через `in`: після перевірки можна читати поле, властиве
// лише серіалам, — і компілятор не заперечує
const title = isTv(item) ? item.name : item.title;
```

У JavaScript-версії те саме написано як `item.title ?? item.name ?? "Без назви"` —
працює, але жодна перевірка не гарантує, що ти не забув третій випадок.
Тут забути не можна: компілятор не пропустить.

## Головне архітектурне рішення: `lib/media.ts`

У макеті три вкладки — «Усі», «Фільми», «Серіали». TMDB віддає їх
різними полями:

| | фільм | серіал |
| --- | --- | --- |
| назва | `title` | `name` |
| дата | `release_date` | `first_air_date` |
| тривалість | `runtime` (число) | `episode_run_time` (масив) |

Різниця гаситься **один раз**, у `normalizeMedia()`, а далі весь застосунок
працює з типом `MediaItem`. Це і є найкорисніший урок цього боса: **дані
з чужого API приводять до свого вигляду одразу на вході, а не розбирають
по місцю використання.** У типізованій версії це правило ще й перевіряється
компілятором: жоден компонент не має доступу до сирих полів TMDB, бо в його
пропсах стоїть `MediaItem`, а не `object`.

## Друге рішення: що зберігати в адресі, а що — в `useState`

У застосунку два шматки стану, і живуть вони в різних місцях **навмисно**:

- **обрана вкладка — в адресі** (`/?tab=movie`);
- **текст у полі пошуку — у `useState`**.

Чому не однаково. У шапці є посилання «Фільми» → `/?tab=movie`. Поки
вкладка лежала в `useState`, це посилання не працювало: адреса змінювалася,
а сторінка лишалася на вкладці «Усі», бо компонент не має звідки дізнатися
про зміну адреси. Щойно вкладка переїхала в адресу, запрацювали і посилання
в шапці, і хлібні крихти, і кнопка «назад».

А текст пошуку в адресі був би шкідливий: він змінюється на кожне
натискання клавіші, тож слово «месники» лишило б **сім** записів в історії.

**Що з цього виходить у типах.** `searchParams.get("tab")` віддає
`string | null` — жодного `TabId` звідти взятися не може, в адресі буває
що завгодно. Перетворює одне на інше `findTab(tabId: string | null)`,
і саме тому вона приймає широкий тип, а повертає вузький. Це загальний
шаблон: **межа з зовнішнім світом приймає те, що є, і віддає те, чому
можна довіряти.**

## Шість місць, де типи справді працюють

**1. Межа з мережею — `src/types/tmdb.ts`.**
`response.json()` повертає `any`. Цей `any` розтікається по всьому
застосунку й тихо вимикає перевірку типів усюди, куди дійшов. Тому межа
проводиться одразу, і **двічі**: сирі типи TMDB окремо, наш `MediaItem` окремо.

**2. `TABS as const` → `TabId`.**
Тип вкладок виводиться із самого масиву. Додаси четверту вкладку —
тип розшириться сам; списки «які вкладки є» і «яка обрана» ніколи
не розійдуться.

**3. `isMediaType()` замість `as MediaType`.**
Сегмент адреси — це будь-який рядок: користувач може набрати
`/title/qwerty/1` руками. Захисник типу перевіряє це насправді;
`as` просто збрехав би компілятору, а застосунок пішов би
робити запит `/qwerty/1`.

**4. Явний тип-параметр там, де тип не виводиться правильно.**
`useState<T | null>(null)` у `useTmdb` — без нього TypeScript вивів би
тип `null`, і `setData(відповідь)` став би помилкою. Те саме правило
для стану з початковим `[]` або рядковим літералом.

**5. `catch (error: unknown)` і `instanceof Error`.**
У JavaScript кинути можна що завгодно — хоч рядок. Тому catch отримує
`unknown`, і читати `.message` можна лише після звуження типу.

**6. `readonly MediaItem[]` у пропсах.**
Підпис «цей масив я не змінюватиму», який компілятор перевіряє.
Спроба `items.push(...)` усередині компонента стане помилкою.

## П'ять речей, на які дивиться ментор

**1. `response.ok` перевіряється руками.**
`fetch` не кидає помилку на 404 чи 500 — він відхиляє проміс тільки коли
запит не відбувся взагалі. Дивись `api/tmdb.ts`.

**2. `AbortController` в очищенні ефекту.**
Користувач швидко друкує «мес» — летять запити. Повернутися вони можуть
у будь-якому порядку, і без скасування на екрані опиняться результати
для «ме», хоча в полі написано «мес». Дивись `hooks/useTmdb.ts`.

**3. Стабільний `key`, а не індекс.**
Ключ склеєний із типу й id: ``key={`${item.mediaType}-${item.id}`}``.
Фільм і серіал можуть мати **однаковий** `id` — вони лежать у різних
таблицях TMDB.

**4. Токен у `.env`, `.env` у `.gitignore`, `.env.example` у репозиторії.**
Усе, що потрапило в історію Git, лишається в ній назавжди.

**5. Усі чотири стани видно.**
Завантаження, помилка, порожній результат і готові дані.

## Дебаунс: чому він тут є

У макеті поле пошуку **без кнопки** — отже, результати мають з'являтися
під час набору. Але запит на кожну літеру — це сім запитів на слово
«месники» і швидко вичерпаний ліміт TMDB.

`useDebounced` тримає два значення: те, що в полі (оновлюється миттєво),
і те, що «встоялося» (йде в запит). Уся його робота — `setTimeout` плюс
`clearTimeout` в очищенні ефекту.

Тип-параметр `useDebounced<T>(value: T): T` тут не прикраса: хук повертає
рівно той тип, що йому дали. Для рядка — `string`, для об'єкта фільтрів —
тип цього об'єкта. Без `<T>` назовні виходив би `unknown`.

## Дрібниці, які легко проґавити

- **Прокрутка після переходу.** react-router не перезавантажує сторінку,
  тому прокрутка лишається там, де була: клацнеш десяту картку —
  і сторінка фільму відкриється прокрученою до середини. Лікує
  `ScrollToTop.tsx`. Він повертає `null` — і тип повернення написаний
  явно, як підпис «розмітки не буде, я тут заради побічної дії».
- **Дата виходу — не `2012-04-25`.** Це формат бази даних. Людині
  показуємо «25 квітня 2012 р.» через вбудований `Intl.DateTimeFormat`,
  а машині лишаємо початкове значення в `<time dateTime>`. Пастка всередині:
  рядок без часу браузер читає як опівніч **за UTC**, а форматує вже за
  поясом користувача — тож без `timeZone: "UTC"` десь у Чикаго та сама
  стрічка вийшла б 24 квітня.
- **Роль ARIA не беруть наполовину.** Вкладки виглядають як `role="tablist"`,
  але ця роль обіцяє читалці ще й `role="tabpanel"`, `aria-controls`
  і перемикання стрілками ← →. Обіцянка без виконання гірша за мовчання:
  користувач почує «вкладка 1 з 3», натисне стрілку — і нічого не станеться.
  Тому тут звичайні кнопки з `aria-pressed`.
- **`NavLink` не підходить для `?tab=movie`.** Він порівнює лише шлях
  адреси — те, що до знака питання. У обох посилань шапки шлях однаковий
  (`/`), тож `NavLink` підсвітив би обидва одразу. Тому звичайний `Link`
  і порівняння параметра вручну.
- **Відступ задає блок, а не його останній нащадок.** Проміжок до
  заголовка розділу колись давали вкладки своїм `margin-bottom`. Щойно
  вкладки ховалися під час пошуку — заголовок злипався з полем пошуку.
- **Адресу пише користувач.** `/title/person/5` чи `/?tab=котики` мають
  показати зрозуміле повідомлення, а не порожній екран. Саме тому
  `useMediaDetails` віддає `isSupported` окремо від `error`: «такої
  сторінки немає» і «не вдалося завантажити» — різні речі для користувача.

## Чого тут навмисно немає

- **`any` — жодного.** Ні явного, ні як тип пропа чи стану.
- **`as` для «прибирання помилки».** Приведень у проєкті два, і обидва
  позначені коментарем: `as T` у `tmdbFetch` (перевірити відповідь сервера
  компілятор не може в принципі — для справжньої перевірки форми беруть
  `zod` або `valibot`) і `tab.id as MediaType` у `useMediaList`, де
  звуження вже сталося в сусідньому виразі.
- **Оклику `!`** (`document.getElementById("root")!`). У `main.tsx`
  замість нього чесна перевірка з помилкою — `!` вимикає перевірку
  саме там, де вона єдина й потрібна.
- **Кешу результатів і пагінації.** Кожен запит іде в мережу; у справжньому
  проєкті взяли б TanStack Query.
- **Токена на бекенді.** У фронтенд-застосунку токен усе одно видно
  у вкладці Network — для навчального проєкту це прийнятно.

## Відхилення від макета

Ті самі, що й у [`example-react-movies`](../example-react-movies#відхилення-від-макета):

- **Шрифт.** У макеті все набрано Poppins, але **Poppins не має кирилиці** —
  українські літери малювалися б системним шрифтом. Тому підключено ще
  Montserrat: браузер підбирає шрифт посимвольно, тож латиниця й цифри
  лишаються в Poppins, як у макеті, а кирилиця дістається Montserrat.
- **Логотип** намальовано вручну (два трикутники), як і іконки пошуку
  й зірочки — набір vuesax і фірмовий знак із макета не експортувалися.
- **Фон** макета — растровий шар 1440×3192; тут ті самі плями зроблено
  двома `radial-gradient`.
- **Тексти українською**, дані запитуються з `language=uk-UA`.
- **Пункт «Suggest me»** з навбару не реалізовано: за ним у макеті немає
  жодного екрана.
- **Назва на картці обрізається** трьома крапками, інакше довгі українські
  назви ламали б рівний ряд карток.

## Перевір себе перед здачею

1. `npm run typecheck` виконує саме `tsc -b` — і завершується без помилок.
2. `grep -rn ": any\|as any\|<any>" src/` — порожньо.
3. У `tsconfig.app.json` і `tsconfig.node.json` немає `"strict": false`
   і жодного окремого послаблення (`noImplicitAny: false` тощо).
   У сучасному TypeScript строгий режим увімкнено типово — головне
   його не вимкнути.
4. Відкрий `/title/qwerty/1` — має бути «Такої сторінки немає»,
   а не запит до TMDB і біла сторінка.
5. Консоль браузера порожня, зокрема без попереджень про `key`.
6. Кожен `useState` із початковим `null`, `[]` або рядковим літералом
   має явний тип-параметр там, де без нього тип вивівся б надто широко.
7. Пошук «asdfgh» — має з'явитися «нічого не знайшлося», а не порожня сітка.
8. Набери щось у пошуку швидко й подивись у вкладку Network: має піти
   **один** запит. У режимі розробки їх буде два — це `StrictMode`
   навмисно виконує ефект двічі. Головне, щоб їх не було сім.
9. Натисни «Фільми» в шапці — має перемкнутися вкладка, а не лише адреса.
10. Погортай каталог, відкрий картку — сторінка фільму має відкритися згори.
11. Звузь вікно до ширини телефона — нічого не має вилазити за край.
    Перевіряй на **320px**, а не на 375.
12. Відкрий стрічку без банера (у TMDB `backdrop_path` часто `null`) —
    панель із назвою має стояти на своєму місці, а не заїжджати під шапку.
